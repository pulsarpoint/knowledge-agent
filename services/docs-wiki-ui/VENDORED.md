# Vendored code

The visual theme and two components are vendored from
[deepwiki-open](https://github.com/AsyncFuncAI/deepwiki-open)
at commit b5e766699b7f0ec5294426af53f5924d9058218b, MIT License,
Copyright (c) 2024 Sheing Ng.

Note (2026-08-03): `app/globals.css` is no longer vendored from deepwiki-open.
Its theme (the Japanese-aesthetic palette and companion utility classes) was
replaced by shadcn/ui's default zinc CSS-variable theme as part of the
shadcn restyle (see `docs/superpowers/plans/2026-08-03-docs-wiki-ui-shadcn.md`).
The file is now original to docs-wiki.

| File | Origin | Local changes |
|---|---|---|
| app/components/Markdown.tsx | src/components/Markdown.tsx | Removed imports `remark-math`, `rehype-raw`, `rehype-katex`, `katex/dist/katex.min.css` (raw HTML must never render — no rehype-raw under any circumstances); dropped `remarkMath` from `remarkPlugins` (kept `remarkGfm`); dropped the now-empty `rehypePlugins` prop entirely. No prop-shape change needed: upstream's `MarkdownProps { content: string }` already matches our required `Markdown({ content }: { content: string })` signature, so no wrapper was added. `./Mermaid` import path and `react-syntax-highlighter/dist/cjs/styles/prism` path left unchanged — verified both resolve under Vite (vitest run + a temporary route-wired production `npm run build`, then reverted). Added (Task 4): upstream's `h1`–`h4` renderers emit no `id`, so DocView's table-of-contents `#anchor` links had nothing to land on. Added a `slugifyHeading`/`headingPlainText` helper and pass `id={dedupeSlug(usedSlugs, headingPlainText(children))}` on each of `h1`–`h4`, using the same slug rule as the API's `slugify` (lowercase, `[^a-z0-9]+` → `-`, trim `-`, fall back to `"section"` if empty) so ids match the `headings[].anchor` values `getDoc` returns. Also mirrors `rag/content.py`'s `_dedupe_slug`/`unique_slugs`: repeated headings get `-2`, `-3`, ... suffixes (first occurrence stays bare), keyed on the base slug exactly like the API — including its same latent quirk where a literal heading slug can collide with a generated suffix (not specially handled, on either side). The `used` counts live in a `usedSlugs` map created fresh in the `Markdown` component body on every render, so one document's dedupe counts never leak into the next render's ids. Added (Task 3, page-level mobile): the `table` override already wrapped tables in `overflow-x-auto` (unchanged, upstream had this). The fenced-code-block wrapper's `overflow-hidden` changed to `overflow-x-auto` — live-verified at 375px that `react-syntax-highlighter`'s `wrapLongLines` (soft-wraps at whitespace via `white-space: pre-wrap`) does not help a single unbroken token with no break opportunities (e.g. a long identifier); without a scrolling container the line silently overflowed past the wrapper's `overflow-hidden` and (compounded by a separate missing `min-w-0` on the shadcn `SidebarInset` primitive — not a deepwiki-open file, see the Task 3 report) forced the whole page to scroll horizontally. `overflow-x-auto` keeps the rounded-corner clipping (any non-`visible` overflow value still clips a box's content to its `border-radius`) while adding a scrollbar for that case. Also added `break-words` to the **inline** `code` renderer — it has no wrapping container of its own, so the same unbroken-token failure mode reproduced live in ordinary prose text; `break-words` lets it wrap in place instead. No changes to sanitization, `dangerouslySetInnerHTML`, or the mermaid/security paths above. |
| app/components/Mermaid.tsx | src/components/Mermaid.tsx | `mermaid` and dynamic `svg-pan-zoom` imports already match package.json, no path adjustment required. Deliberate security hardening (no longer byte-identical): `mermaid.initialize`'s `securityLevel` changed from upstream's `'loose'` to `'strict'`. The rendered SVG is inserted via `dangerouslySetInnerHTML`, and mermaid fences can originate from model answers as well as docs — `'loose'` allows scriptable content inside that SVG, which would violate the "model output is never rendered as HTML" invariant. No other behavioral change. Further hardening (final-review wave): the render-error catch path (currently unreachable in practice, since `suppressErrorRendering: true` keeps mermaid itself from throwing on most malformed charts) previously interpolated the untrusted `chart` string directly into an `innerHTML` template — an undocumented raw-HTML sink. Changed to set only static markup via `innerHTML` and write `chart` through `textContent` on the `<pre>` instead, so untrusted chart text can never be parsed as HTML. Also (2026-08-03, Task 4 follow-up): wrapper chrome UI (modal header, zoom buttons, loading spinners, error panel) re-pointed from deepwiki CSS variables to shadcn tokens: `var(--accent-primary)` → `var(--primary)`, `var(--border-color)` → `var(--border)`, `var(--card-bg)` → `var(--card)`, `var(--highlight)` → `var(--destructive)`. Additional fixes: captions/hints (zoom-percent readout, error hint, rendering caption) changed from `text-[var(--muted)]` (a surface token in shadcn, not foreground) to `text-[var(--muted-foreground)]` for legibility in both themes; fullscreen modal's dead deepwiki classes `shadow-custom card-japanese` replaced with `border shadow-lg` to restore border/shadow styling. No changes to diagram rendering, SVG injection, or securityLevel. |

Everything else in this package is original to docs-wiki.
